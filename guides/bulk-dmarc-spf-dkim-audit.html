How to bulk-check DMARC, SPF and DKIM for a whole client list

Who this is for: MSPs, IT providers, deliverability consultants and agencies that look after email for many domains and want one table showing who is exposed to spoofing, and what DNS record fixes it.

Tool used: DMARC Checker – Bulk DMARC, SPF & DKIM Email Security Audit (Apify Store, pay per domain).

What you get per domain

One row per domain with, among others:

  • dmarcPolicy (reject, quarantine, none or missing), dmarcPct, alignment and rua/ruf reporting addresses
  • spfEnforcement (-all, ~all, ?all, +all or missing), spfIncludes and spfLookupCountEstimate, with spfExceeds10LookupLimit flagging the RFC 7208 10-lookup limit
  • activeDkimSelectors: DKIM keys found by probing 13 common selectors (for example google, selector1, selector2, k1)
  • BIMI, MTA-STS, TLS-RPT and CAA presence, MX provider (emailProvider) and any secure email gateway
  • spoofingRiskLevel (CRITICAL, HIGH, MODERATE, LOW) and scores for email and web-header security
  • recommendedDnsRecords: copy-paste DMARC/SPF records for each gap

Everything is read from public DNS and public HTTP headers. Nothing is sent to the domain's mail server.

Step 1: Collect the domains

Export the client or prospect list from your CRM, PSA or spreadsheet and keep just the domain column. Website URLs and bare domains both work; duplicates are fine.

Step 2: Run the Actor

  1. Open the Actor page and click Try for free (a free Apify account comes with monthly platform credit).
  2. Paste your domains into Target Domains, or switch to the JSON editor and use:
{
  "domains": ["clientone.com.au", "clienttwo.com", "https://www.clientthree.co.uk"],
  "probeDkimSelectors": true,
  "checkHttpSecurityHeaders": true,
  "generateRemediationPack": true,
  "maxConcurrency": 10,
  "requestTimeoutSecs": 5
}
  1. Click Start. Results appear in the Output tab as rows finish. Export CSV, Excel or JSON from there.

Step 3: Triage the results

A simple order that works for most lists:

  1. No DMARC record (dmarcPolicy missing): anyone can send mail as the domain and receivers get no policy.
  2. p=none: monitoring only. Spoofed mail is still delivered. Check dmarcRua is set so reports go somewhere before you tighten the policy.
  3. SPF problems: +all or ?all, a missing record, or spfExceeds10LookupLimit: true (SPF permerror risk).
  4. No DKIM selector found: either DKIM is not set up, or it uses a selector outside the 13 probed. Confirm with the client's mail platform before calling it missing.

Sort by spoofingRiskLevel, then filter on dmarcPolicy. The recommendedDnsRecords field gives a starting record for each fix. Review it before publishing: a DMARC rua address and the SPF include list must match the services the domain actually sends from.

FAQ

Does it send test emails? No. It only reads public DNS records and public HTTP headers.

Can it prove DKIM is missing? No. DKIM selectors can be any name. The Actor reports the selectors it found among 13 common ones, so treat "none found" as "check with the mail platform".

Can I use it from an AI agent? Yes, through the Apify MCP server: https://mcp.apify.com/?tools=ausbizstack/b2b-email-security-dmarc-spf-auditor.
